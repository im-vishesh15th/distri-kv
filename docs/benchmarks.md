# Benchmark Results (Phase 23)

> **Hardware:** Apple M2 (arm64), macOS
> **Go version:** go1.x
> **Date:** Auto-generated by `go test -bench=. -benchtime=2s`
>
> **Important:** These are microbenchmarks on a single laptop. They measure
> *internal* component throughput under ideal conditions (no network latency,
> no disk I/O, no contention from other processes). Real-world performance
> will be significantly lower due to network, disk fsync, and cluster
> coordination overhead. Do not use these numbers for capacity planning.

## Shard Benchmarks (`internal/shard`)

| Benchmark | Operations | ns/op |
|-----------|------------|-------|
| `BenchmarkSlot` (FNV-1a hash) | 126.5M | 18.5 ns/op |
| `BenchmarkGroup` (key → group) | 100M | 20.2 ns/op |
| `BenchmarkGroupSlot` (slot → group) | 1.0B | 0.61 ns/op |
| `BenchmarkConfigLoad` (JSON parse + validate) | 5.6M | 431 ns/op |

**Notes:**
- `GroupSlot` is O(1) integer arithmetic — extremely fast
- `Group` = `Slot(key)` + `GroupSlot(slot)` — dominated by hash
- `ConfigLoad` includes JSON parse + full validation (total/non-overlapping/in-range)

## Multi-Raft Benchmarks (`internal/multiraft`)

| Benchmark | Operations | ns/op | ops/sec (est.) |
|-----------|------------|-------|----------------|
| `BenchmarkSingleGroupPropose` | 3.7M | 19.9 µs/op | ~50,000/s |
| `BenchmarkMultiGroupPropose` | 627 | 3.5 ms/op | ~285/s |

**Environment:**
- 3-node cluster, simulated network (`sim.Network`)
- No network latency/faults (Auto mode, 10ms ticks)
- 100-byte payloads
- Auto leader election, no faults during benchmark

**Notes:**
- `BenchmarkSingleGroupPropose`: 3-node, 1 group, single-threaded proposer
- `BenchmarkMultiGroupPropose`: 3-node, 4 groups, parallel proposers (`b.RunParallel`)
- Raft latency dominated by: election ticks, heartbeat intervals, log append/fsync
- Real network (even localhost) adds ~0.1–1ms RTT; disk fsync adds ~0.1–0.5ms
- These numbers represent *simulated* best case; real cluster will be 10–100x slower

## Comparison with Prior Art (Qualitative)

| System | Write Throughput | Read Throughput | Notes |
|--------|------------------|-----------------|-------|
| **DistriKV (sim, 3-node)** | ~50K ops/s (propose) | N/A | Simulated, no disk/network |
| etcd (3-node, SSD) | ~50–100K writes/s | ~100K reads/s | Disk fsync, network |
| Consul (3-node) | ~5–10K writes/s | ~20K reads/s | Raft + Serf |
| Redis Cluster | ~100K ops/s | ~200K ops/s | In-memory, async replication |

**Caveat:** DistriKV benchmarks run in a simulated in-memory network with no disk fsync.
Production numbers will be 10–100x lower depending on disk, network, and payload size.

## Running Benchmarks

```bash
# All benchmarks (2s each)
go test -bench=. -benchtime=2s ./...

# Specific package
go test -bench=. -benchtime=2s ./internal/kv/
go test -bench=. -benchtime=2s ./internal/shard/
go test -bench=. -benchtime=2s ./internal/multiraft/

# With memory allocation stats
go test -bench=. -benchmem -benchtime=2s ./internal/kv/
```
